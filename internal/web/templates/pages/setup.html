  1. {{if .Status.HasCostSource}}✓{{else}}1{{end}}

    Connect a cost source

    {{if .Status.HasCostSource}}Connected · {{.Status.CostProvider}}{{else}}Not connected{{end}}

    This is where costblame reads your cloud bill from, so it has something to compare against a rolling baseline and flag as a spike. Built-in adapter: AWS Cost Explorer.

    1. Make sure the machine running costblame can already authenticate to AWS — an instance role, a shared credentials file, or the usual AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY env vars. costblame uses the default AWS credential chain; it doesn't take credentials directly.
    2. Open costblame.yaml (or create it next to the binary) and add: 
      cost:
  provider: aws
  aws:
    region: us-east-1
    granularity: DAILY
    3. Or skip the file entirely and set env vars instead: 
      COSTBLAME_COST_PROVIDER=aws
COSTBLAME_COST_AWS_REGION=us-east-1
    4. Restart costblame serve. This step is checked off as soon as the process starts with a provider configured — you don't need working credentials yet to see it turn green, but the poller will log a real error until they're valid.
  2. {{if .Status.HasDeploySource}}✓{{else}}2{{end}}

    Connect a deploy source

    {{if .Status.HasDeploySource}}Connected · {{range $i, $s := .Status.DeploySources}}{{if $i}}, {{end}}{{$s}}{{end}}{{else}}Not connected{{end}}

    This is where costblame learns what shipped, so it has something to blame a cost spike on. Pick exactly one to start.

    1. Option A — GitHub Actions. In costblame.yaml: 
      sources:
  github:
    webhook_secret: "<a secret only you and GitHub know>"
    token: "<optional GitHub token, enables PR/changed-files enrichment>"
    deploy_workflows: ["Deploy"]   # optional — which workflows count as deploys
      or the env vars GITHUB_WEBHOOK_SECRET / GITHUB_TOKEN. An empty secret is refused on purpose — costblame won't mount an unsigned receiver.
    2. Option B — GitLab CI. 
      sources:
  gitlab:
    webhook_secret: "<a secret only you and GitLab know>"
    3. Option C — ArgoCD. Opt-in, and a token is required. Configure ArgoCD's webhook notification to send it as an Authorization: Bearer header: 
      sources:
  argocd:
    enabled: true
    token: "<a token only you and ArgoCD know>"
    4. In your CI/CD tool's webhook settings, point it at POST /webhooks/<github|gitlab|argocd> on this server's address.
    5. Restart costblame serve — this page checks that status again automatically every few seconds.
